* **OpenCode webfetch: dual implementation in opencode vs core packages**: Two webfetch implementations exist: \`packages/opencode/src/tool/webfetch.ts\` (legacy, registered as \`tool.fetch\`) and \`packages/core/src/tool/webfetch.ts\` (newer). Key differences: core version uses \`collectBoundedResponseBody\` (streaming bounded collection, fails as soon as accumulated bytes exceed cap); opencode legacy buffers entire body first (pre-checks content-length header, post-download checks arrayBuffer.byteLength). * **OpenCode webfetch: stripping layers and the real bottleneck**: Three distinct stripping levels exist: (1) tag-level — already done by TurndownService in legacy webfetch; (2) block-level boilerplate removal (nav/footer/sidebar/ads) — NOT implemented anywhere, requires @mozilla/readability + linkedom; (3) section extraction — only in BYK's gist, brittly. The real bottleneck for problem pages is the fetch layer (anti-bot walls, JS-rendered content), not conversion/stripping. Positional truncation (Truncate service cuts at 50KB/2000 lines from head) is the main risk from boilerplate, but empirically most pages fit under the cap. Per-site fallbacks (e.g., old.reddit.com for Reddit) are higher-leverage than a readability pass. Turndown already produces clean readable markdown when fetch succeeds.

### Gotcha

<!-- lore:019eccc4-5836-7bdd-b2b4-96f927609815 -->
* **Git rebase in dumb terminal: EDITOR unset causes commit message failure**: Trap: during \`git rebase\` in a dumb terminal (e.g. agent shell), git tries to open an editor to confirm the commit message and fails with 'Terminal is dumb, but EDITOR unset / Please supply the message using either -m or -F option.' Looks like a rebase conflict but is actually a missing EDITOR env var. Fix: set \`GIT\_EDITOR\` or \`EDITOR\` to a script that exits 0 (e.g. \`true\` or \`cat\`) before running the rebase, or use \`git rebase --continue\` with \`GIT\_EDITOR=true\` prepended.

<!-- lore:019dea5a-9d98-7749-8128-37bc6d28ffb2 -->
* **Lore worker model auto-selection pipeline never wired into production**: \`packages/core/src/worker-model.ts\` exports \`selectWorkerCandidates\`, \`computeModelFingerprint\`, \`storeValidatedWorkerModel\`, \`isValidationStale\`, \`structuralCheck\`, and the LLM judge prompt — all unit-tested but NEVER called from production code. \`resolveWorkerModel()\` only checks \`getValidatedWorkerModel()\` which always returns null (kv\_meta has no \`lore:worker\_model:\*\` keys). Result: \`getWorkerModel()\` in \`packages/opencode/src/index.ts\` always falls through to \`configModel\` (session model, typically Opus). All \`backgroundDistill\`/\`backgroundCurate\`/compaction calls run on Opus instead of Sonnet. Quick fix: set \`workerModel: { providerID, modelID }\` in \`.lore.json\`. Proper fix: wire validation flow to populate kv\_meta. Cost impact: ~$2,270 of $2,781 Lore worker spend (82%) is recoverable by routing distill/curate to Sonnet.

<!-- lore:3ed3e973-7706-464a-afa9-2152c55e7b6a -->
* **Nuum eval sessions pollute session list without hidden root**: Nuum eval harness must create all eval sessions as children of a hidden root session — OpenCode hides child sessions from the main list. Without this, eval runs produce ~4000 top-level sessions. The eval root is created once in main() before the concurrency pool starts. Also: backfilled distillations for actively-used sessions get replaced when the live plugin runs distillation cycles — only inactive sessions retain stable backfilled segments.

<!-- lore:bb4dd0c6-f96e-48d5-b547-134f8a0b0b13 -->
* **Nuum FTS5 content-sync purge: must rebuild index after content table deletes**: When temporal messages are deleted from the temporal\_messages content table (e.g., during orphan reset or cleanup), the FTS5 index (temporal\_fts) becomes stale because FTS5 content= tables don't auto-sync deletes. Fix: rebuild the FTS5 index after content table deletes using INSERT INTO temporal\_fts(temporal\_fts) VALUES('rebuild'). Committed as 1d02e1d. Without this, FTS5 searches can return stale results or crash on deleted rowids.

<!-- lore:019cab46-2cf6-71e0-9eac-99a8785ba1d7 -->
* **OpenCode binary: OPENCODE\_MIGRATIONS define required for compiled binaries**: OpenCode compiled binaries require \`OPENCODE\_MIGRATIONS\` define. Without it, \`import.meta.dirname\` resolves to \`/$bunfs/root\`, causing \`path.join\` to point to non-existent \`/$bunfs/migration\`, crashing TUI with \`ENOENT\`. The define must contain serialized migration SQL at build time. Stable release builds must set this; dev scripts were previously missing it.

<!-- lore:019de804-8b89-7b3c-8907-6ac77f87e758 -->
* **OpenCode persisted() ready signal: sync on web, async on desktop**: OpenCode \`persisted()\` helper returns a \`ready\` signal via \`createResource\`. On web (localStorage), \`init\` is sync, so \`ready()\` is true immediately. On desktop (platform.storage), \`init\` is async. Implication: \`\<Show when={isReady()}>\` gates pass synchronously on web for providers. Bootstrap data fetching (4 parallel API calls) does not block rendering; \`GlobalSyncProvider\` renders children unconditionally. Web loading screen is network time, not bootstrap.

""}\`), triggering the nearest \`\<Suspense>\` boundary. Fix: remove JSX read entirely; the fetcher runs reactively from its source signal regardless of read status.
