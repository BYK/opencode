* **AGENTS.md/.lore.md tracked status differs per branch, blocks rebase**: Trap: \`git rebase\` (incl. interactive autosquash) on opencode fork branches fails with 'cannot rebase: you have unstaged changes' — looks like a stray manual edit, but AGENTS.md/\`.lore.md\` get auto-regenerated in the working tree by the lore tool before the rebase even starts, recurring across sessions. So 'discard the change' isn't one universal fix: if untracked, delete/reset it; if tracked (as on byk/cumulative), the dirty state is an uncommitted DELETE — restore it via \`git checkout -- .lore.md\` instead of trying to discard a delete. * **Dependabot PR pile-up: stale lockfile base, not real conflicts**: When many Dependabot PRs accumulate (e.g. 25+ on the byk.github.io Astro repo), every PR shows CONFLICTING/DIRTY against master. Trap: looks like each dependency bump conflicts with the others. Actually each PR patches pnpm-lock.yaml/package.json against the base at PR-creation time; as master moves forward every PR's base independently goes stale, so lockfile diffs no longer apply cleanly — it's N independent stale-base conflicts, not real semantic clashes. Fix: don't merge PRs one-by-one; regenerate the lockfile fresh against current master (bump versions in one batch commit or re-run dependabot after a clean rebase), then close the now-redundant stale PRs. Related to \[\[019f8216-fa51-73f7-9cf8-2375c1656019]] (PR/branch upkeep workflow).
